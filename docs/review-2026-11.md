# Review of November 2026: what runs, what is only written, what is left

Written for the v0.2.1 release, against the AIPE goals: open, provenance-tracked engineering work that
agents execute and people review. Items marked **fixed** were changed in v0.2.1; the others are open, each
with a proposal. Nothing here was verified on hardware.

## What actually runs

| Part | Evidence |
| --- | --- |
| `aipe_simulation.ngspice`: locate, qualify, run, parse raw files | executed in CI on Ubuntu (ngspice 42); also run on Windows (ngspice 47) |
| `aipe_simulation.dab`: Level 1 and Level 2 netlists and runner | executed in CI; Level 2 compared with the Windows record ([validation.md](validation.md)) |
| `aipe_simulation.waveforms`: dataset, steady state, metrics, DAB summary | unit tests on synthetic waveforms plus the executed runs |
| `aipe_simulation.control`: plant, loop design, closed-loop simulation | unit tests; the open-loop power law is compared with ngspice Level 1 at three phase shifts |
| `pe-python-control-analysis` buck example, `pe-ngspice-switching-validation` buck netlist | executed in CI |

A full test run takes about 15 s; the Level 2 simulation takes 7 s of that.

## What is a written procedure only

Eleven of the thirteen skills are text for an agent to follow. This repository contains no code that
executes them and no recorded run of them:

- LTspice, PLECS, MATLAB/Simulink, SIMetrix/SIMPLIS, ANSYS, COMSOL (six skills). Each needs the user's own
  installation and licence; each says so in its `Accessibility` section and in `skills.json`. No vendor
  binary, model, library or example file is bundled: the skill folders hold Markdown, one `openai.yaml`
  each, one ngspice netlist and one Python script, all written for this repository.
- Control-loop debugging and DSP/FPGA debugging (two skills): checklists and diagnosis procedures.
- FreeCAD packaging, KiCad power-stage review, open FEA problem setup (three skills, labelled `scaffold`).

## Problems fixed in v0.2.1

- **No licence.** Now MIT.
- **The README's first simulation command reported an invalid result and still exited 0.** The default
  circuit starts from zero current and needs about 130 cycles; the default is 24. Added
  `--analytic-start`, and exit code 2 for a completed but invalid run.
- **CI never executed the Level 2 model**, the one the 10 kW workflow consumes. It does now.
- **The waveform file had no written specification.** Added, with a test that pins it.
- **Documentation drift**: Level 2 loss quoted as 136 W (recorded: 132 W); reproduction commands that did
  not reproduce the table next to them; a validation record that still described five tests.

## Open problems and proposals

1. **`maturity: usable` overstates the proprietary-tool skills.** In `skills.json` the six vendor-tool
   skills and the two debugging skills are `usable`, the same word used for the ngspice skill that has
   executed evidence. Nobody has run them through AIPE. *Proposal:* split the field into
   `procedure` (draft / reviewed) and `execution_evidence` (none / example / ci), in the same change that
   updates the Registry manifest wording. Not done now because it changes `skills.json`, which other tools
   read.

2. **The CAD, PCB and FEA scaffolds overlap repositories that now exist.** AIPE-CAD-Agent, AIPE-PCB-Agent
   and AIPE-Field-Simulation are indexed in the Registry and own those subjects. *Proposal:* when each of
   them graduates, replace the scaffold here with a pointer or move the text there. Not done now because
   those repositories are still incubating.

3. **The skills are packaged for one agent product.** Each has `agents/openai.yaml` and the instructions
   say "Codex". The `SKILL.md` files themselves are portable. *Proposal:* describe installation neutrally
   and keep the product-specific file as one option.

4. **Level 2 conduction loss uses one on-resistance (58.7 mOhm) for all eight switches**, which overstates
   the secondary bridge, and Coss is linear. The loss figure is therefore a behavioural estimate, not a
   device-level result. *Proposal:* per-bridge switch parameters in `DabCircuitSpec` (an additive change),
   fed from AIPE-Semiconductor-Database once it is released. Level 3 (manufacturer models) remains
   unexecuted and should stay labelled so.

5. **No validation beyond one solver.** Level 1 agrees with the analytic lossless model, and ngspice 42
   agrees with ngspice 47. There is no comparison with a second simulator or a measurement.
   *Proposal:* keep the wording as it is ("executed", never "validated") until a measurement exists.

6. **The control baseline is checked only in open loop against the circuit.** The closed-loop scenarios
   run on the cycle-averaged plant; no closed-loop switching simulation exists. *Proposal:* one
   ngspice-in-the-loop step-load case, when the control step of the workflow needs it.

7. **Tests contain a path on the author's disk** (`D:/Cursor Workspace/...` as the default
   `AIPE_TOOLS_DIR`, and as a search location for an optional AIPE-Design-Agent cross-check). Harmless
   elsewhere, since the default is ignored when the directory is absent, but it does not belong in a
   public repository. *Proposal:* remove the defaults once the author's machine sets `AIPE_NGSPICE`.
   Left alone now so that the author's local test run keeps working.

8. **Only single-phase-shift DAB.** The package name promises simulation skills in general; the executable
   part covers one topology and one modulation. That is the honest scope today and the README says so.
   Other topologies should come from a need in a workflow, not ahead of one.

9. **Solver version drift is unpinned.** CI uses whatever ngspice the Ubuntu image ships (42 today). The
   Level 2 test tolerances (0.1 % on power, 3 % on loss) will flag a version that behaves differently.
   *Proposal:* nothing more until that happens.

## For other repositories

- **AIPE-Workflows**: no import or call it uses has changed. Its adapters write
  `https://github.com/FulongLi/AIPE-Simulation-Skills` into evidence sources and its CI checks out
  `FulongLi/AIPE-Simulation-Skills`; both should become `AIPE-Labs` and, for CI, the `v0.2.1` tag. Its
  workflow does not install ngspice (`-m "not solver"`); `sudo apt-get install -y ngspice` on the runner is
  all the simulation step needs. Recorded paths such as `D:\...\ngspice_con.exe` in `run.json` and in the
  dataset metadata are provenance of that run, and a new run records its own.
- **Readers of `waveforms.h5`**: the format is unchanged; see [waveform-dataset.md](waveform-dataset.md).
